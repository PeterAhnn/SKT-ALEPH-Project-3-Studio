# 저장·복원 v2

2026-09-21 검토에서 큰 사진을 포함한 세 번째 템플릿 저장 실패, JPEG 재압축, 손상 원본 대신 빈 백업 생성이 재현되어 수정했다.

## 데이터와 이전

IndexedDB `jjal-studio-v2`의 `workspace`에는 현재 편집과 템플릿의 이미지 ID를, `images`에는 ID와 Blob을 저장한다. ID는 이미지 바이트의 SHA-256이다. 같은 사진은 한 번만 보관한다. 문서·새 이미지·더 이상 사용하지 않는 이미지 삭제는 하나의 readwrite transaction으로 처리한다. 실패하면 모두 롤백한다. 쓰기는 순서대로 처리하고 문구 자동 저장은 180ms 지연한다. 저장 중 또는 실패 상태로 페이지를 떠나면 브라우저 확인을 요청한다. 브라우저가 강제 종료되는 경우까지 보장하지는 않는다.

처음 열어 v2 문서가 없으면 `localStorage['jjal-studio-v1']`를 검증하고 사진을 정규화한 뒤 한 번에 이전한다. 이전 원본 키는 지우거나 수정하지 않는다. v2가 있으면 이후에는 v2를 기준으로 사용한다. 성공한 이전은 새로고침마다 반복하지 않는다. 화면 테마 저장은 기존 키를 유지한다.

자료를 읽거나 이전하지 못하면 자동 저장과 일반 백업을 차단한다. 원본을 읽을 수 있는 경우 「손상 원본 다운로드」로 원문을 보관한다. v1 원문은 문자열 그대로, v2는 이미지 데이터를 포함한 복구 JSON이다. 정상 JSON을 전체 검증한 뒤 사용자가 적용하면 저장을 재개한다. 임의로 불완전한 템플릿을 삭제하거나 일부만 가져오지 않는다.

## 이미지와 백업

PNG/JPEG를 실제 헤더와 디코딩으로 검증하고 긴 변 최대 1920px의 PNG로 저장한다. 업로드 또는 외부 백업 복원 때 다시 그리므로 위치 정보 등 원본 메타데이터를 제거한다. JPEG의 이미 존재하는 손실을 복구한다는 의미는 아니며 이후 백업·복원에서는 JPEG 손실 압축을 반복하지 않는다. 이미지 다운로드만 사용자가 선택한 PNG/JPEG 형식으로 인코딩한다.

백업 v2는 `{version:2,current,templates,images:[{id,data}]}`다. 현재 작업과 템플릿의 `image`는 ID 또는 null이고 images에는 고유 이미지 데이터만 포함한다. 이미지 누락·중복 ID·미사용 이미지·필수 편집 항목 누락은 거부한다. v1의 인라인 이미지 백업은 계속 가져올 수 있다. v2를 구버전 편집기에서 읽는 기능은 제공하지 않는다.

사진을 정규화한 뒤 템플릿 ID·문구·배치·폰트와 함께 저장한다. 가져오기 미리보기에는 아직 저장하지 않으며 명시적 복원 버튼을 눌러야 교체한다. IndexedDB에 쓰는 도중 실패해도 화면과 기존 저장 자료는 유지한다.

## 용량 정책과 측정 한계

- 업로드: 기존 12MiB, 24,000,000화소, 한 변 16,000px 상한 유지. 과제 지정 수치가 아니라 입력 자원 보호를 위한 구현 정책이다.
- 정규화: 긴 변 1920px. 스토리 출력 높이 1920px를 고려해 이전 1600px보다 높였다. 사진 비율과 채우기 자르기에 따라 확대가 생길 수 있다.
- 정규화 이미지: 데이터 URL 문자열 24MiB, 디코딩 전 파일 20MiB 상한. 1920×1920 RGBA 원시 픽셀은 약 14.1MiB이다.
- 사진 자산 데이터 URL 합계 64MiB. 내보낸 v2 백업을 다시 받을 수 있도록 파일 입력 상한은 80MiB다. 무제한은 아니며 브라우저의 자체 저장 여유가 먼저 부족할 수 있다.
- 새 기준의 1200×1200 세 종류 고정 시드 JPEG(각 약 1.26MB)를 모두 템플릿으로 저장하고 CRUD·반복 JSON 복원·중복 제거를 실제 검사했다.
- 이 데스크톱 Chromium에서 단색 6000×4000 PNG를 업로드하고 저장할 때 약 391ms였다. 24MP 초과 입력은 기존 작업을 유지하며 거부했다. 단색 합성 이미지 한 건의 수치이므로 복잡한 사진·모바일 전체 성능의 근거나 최적 제한값이라고 주장하지 않는다.

## 재현 검사

모든 브라우저 검사는 사용자 작업과 분리한 QA 출처에서 gstack browse로 수행한다. Node 33건과 기존 편집 30건·폰트 41건·복원 UI 12건에 더해 다음을 실행한다.

1. `tests/storage-browser.js`: 큰 사진 3종, 중복 제거, CRUD, 반복 복원 픽셀 동일, 작은 글자 경고. 이후 실제 reload로 문구·템플릿·사진 수를 확인한다.
2. 새 로컬 포트에서 `migration-seed-browser.js` → reload → `migration-check-browser.js`: v1 원본 보존과 사진 포함 3개 이전.
3. 같은 QA 출처에서 `recovery-seed-browser.js` → reload → `recovery-check-browser.js`: v2 손상, 원본 내보내기, 정상 복구.
4. `legacy-recovery-seed-browser.js` → reload → `legacy-recovery-check-browser.js`: 이전 형식 손상과 부분 이전 방지. seed는 해당 QA IndexedDB를 비운다. 로컬 출처만 허용한다.
5. `image-boundary-browser.js`: 24MP 정상 입력과 초과 입력의 보존.

검사 파일은 정적 배포 dist에 포함하지 않는다. 과거 qa의 수정 전 증거를 덮어쓰지 않으며 새로운 결과는 v2 접두사로 보관한다.
